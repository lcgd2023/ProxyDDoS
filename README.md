# HTTP 压力测试工具 · 使用说明（httptest）

> ⚠️ **仅用于已获得完整书面授权的自有服务器性能测试，禁止用于未授权目标。**
> 图形界面必须勾选「我已获得该目标的完整书面授权」才能开始；命令行启动前也会打印同样的警告。

命令行 `http_pressure_test.py` 与图形界面 `http_pressure_test_gui.py` **共用同一条 `run_test()`**，
并发、时长、超时、代理轮换、统计口径完全一致，两边结果可直接对比。

---

## 1. 安装（一键）

依赖只有一个：`aiohttp`（其余在 `requirements.txt` 里的是爬虫用的）。

| 方式 | 操作 |
|---|---|
| **一键安装** | 双击 `一键安装依赖.cmd`（自动找 Python → 装依赖 → 自检 `import aiohttp` → 显示版本） |
| 手动 | `python -m pip install -r requirements.txt` |
| 国内加速 | `python -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple` |
| 只装压测所需 | `python -m pip install "aiohttp>=3.9"` |

要求：Python **3.8+**（本机实测 3.13）、Windows / Linux / macOS 均可。

安装完自检：

```powershell
python -c "import aiohttp; print(aiohttp.__version__)"
```

## 2. 快速开始

### 图形界面

双击 `打开HTTP压测工具.cmd`（无黑窗；要看异常就用 `python http_pressure_test_gui.py`）：

1. 填**目标地址**（如 `http://127.0.0.1:8080/`）
2. 选**代理 txt**（可留空 = 用本机 IP）
3. 调 **并发 / 时长 / 超时**，按需填 **上传体 / 流量上限**
4. 勾选授权确认 → 点 **▶ 开始测试**，结束可「复制报告」/「导出报告…」

### 命令行

```powershell
# 最简：5 并发跑 30 秒
python http_pressure_test.py http://127.0.0.1:8080/

# 常用：走代理、20 并发、60 秒、超时 5 秒
python http_pressure_test.py http://1.2.3.4/ -p proxies.txt -c 20 -d 60 -t 5

# 上传 64KB 请求体，总流量到 500MB 才停（不写 -d = 时长不限）
python http_pressure_test.py http://1.2.3.4/ -c 20 -b 64k --max-traffic 500m
```

运行中按 **Ctrl+C** 随时停止（等在途请求收尾后照常出报告）。

## 3. 参数速查

| 命令行 | 图形界面对应 | 默认 | 说明 |
|---|---|---|---|
| `<url>`（位置参数） | 目标地址 | — | 只支持 `http` / `https`；不带 scheme 会自动补 `http://` |
| `-p, --proxies` | 代理 txt 下拉框 / 浏览… | 无 = 本机 IP | 每行一个代理，`#` 开头是注释 |
| `-c, --concurrency` | 并发 | 5 | 最大并发连接数（CLI ≥1；GUI 1~1000） |
| `-d, --duration` | 时长(秒) | 30 | **填了流量上限且未显式给 `-d` 时不生效**（见 §5） |
| `-t, --timeout` | 超时(秒) | 10 | 单个请求超时（GUI 1~120） |
| `-b, --body-size` | 上传体 | `0` | 每请求请求体大小，`0` = GET；可写 `512` / `64k` / `2m` / `1g`，单请求上限 64 MB |
| `--max-traffic` | 流量上限 | 空 = 不限 | 总流量（上行+下行）到量即停，如 `500m`、`1t` |
| — | 授权勾选 | 未勾选 | GUI 强制勾选才可开始 |

非法输入会打印 `❌` 并终止，例如：

```
❌ 上传体大小格式不对：'abc'（示例：512、64k、2m、1g）
❌ 单请求上传体最大 64.00 MB（输入了 100.00 MB）
```

## 4. 输出解读

### 进度行（每 2 秒一条，GUI 是 8 张指标卡 + QPS 曲线）

```
⏱️  已运行 30s | 已发送: 1164 | 成功: 1164 | 失败: 0 | 流量: 75.63 MB/80.00 MB (94.5%) | 上行: 73.20 MB | 当前QPS: 38.5
```

设了流量上限时中间那段是**流量完成度**；没设则显示 `成功流量: 628.60 KB`。

GUI 卡片：**总请求 / 成功 / 失败 / 当前 QPS / 峰值 QPS / 平均响应 / 成功流量 / 上行流量**。

### 结束报告

```
📊 测试完成报告
⏱️  总测试时长: 32.06 秒
📤 总请求数: 1232
✅ 成功请求: 1232 | ❌ 失败请求: 0
⚡ 每秒请求数(QPS): 38.43
⏳ 平均响应时间: 1.38 ms
📶 成功流量(下行): 2.57 MB（平均 2.14 KB/个 · 82.12 KB/秒）
⬆️  上行流量: 77.48 MB（平均 64.40 KB/个 · 2.42 MB/秒）
🔢 总流量(上行+下行): 80.05 MB
🔢 状态码分布:
    HTTP 200: 1232 次 (100.0%)
```

| 字段 | 口径 |
|---|---|
| **QPS** | 总请求数 ÷ 总时长（含失败请求） |
| **平均响应时间** | 成功请求的耗时平均值（从发请求到读完 2048 字节响应体） |
| **📶 成功流量(下行)** | **只统计成功请求** = 响应头（状态行 + 各头部字段 + 结尾空行）+ **实际读到的响应体**；每个成功最多读 2048 B；aiohttp 已自动解压 gzip/deflate，算的是**应用层字节**而非网线字节 |
| **⬆️ 上行流量** | **只统计成功请求** = 请求头（按字段估算，含自动补的 Host / Content-Length）+ 请求体；纯 GET 时就是请求头（实测约 341 B/个） |
| **🔢 总流量** | 上行 + 下行，也是「流量上限」的判定口径 |
| **状态码分布 / 失败原因** | 有响应就算成功（含 4xx/5xx）；失败按异常类型 + 错误码归类，如 `TimeoutError`、`ClientOSError(错误码 1225)` |

> 口径不变量：无论填不填上传体/流量上限，**QPS、平均响应时间、成功/失败判定都不变**——
> 这两个新功能只是"多发点数据"和"多一个停止条件"。

## 5. 停止条件（重要）

| 设置 | 行为 |
|---|---|
| 只填 **时长**（流量上限留空） | 到秒数停（原行为） |
| 只填 **流量上限**（如 `1t`，**不给 `-d`**） | **时长完全不参与**：跑多久都行，上行+下行累计到目标流量才停 |
| **显式**给了 `-d` + 流量上限 | 两者**谁先到谁停**（多一道时间保险）；GUI 填了上限就只按流量跑，没有这个选项 |
| 中途手动停 | CLI 按 `Ctrl+C`；GUI 点 `■ 停止`（等在途请求收尾后再出报告） |

流量到顶时：

- 命令行打印 `🛑 总流量已达上限 80.00 MB，自动停止`
- GUI 状态栏变成「已达流量上限」
- **不再发新请求**，在途请求收尾后出报告 → 实际值会略超一个在途请求的量

跑 1TB 之前先算时间：本机回显实测上行约 2.4 MB/s，**1TB ≈ 48 小时**。
另外目标若一直失败、一个字节都攒不到，流量永远到不了顶（会一直跑），记得 `Ctrl+C`。

## 6. 代理文件格式

```text
# 注释行
1.2.3.4:8080
http://5.6.7.8:3128
https://9.9.9.9:8443
```

- 每行一个，`#` 开头是注释，行尾逗号会被去掉
- **裸 `ip:port` 自动补 `http://`**（aiohttp 不认裸地址，否则请求发不出去、100% 失败）
- **`socks4://` / `socks5://` 本工具不支持**（要 `aiohttp-socks`），加载时跳过并提示条数
- 测试时**随机轮换**这些代理；不选文件 = 全程用本机 IP

## 7. 常见问题

**Q：全是失败？**
先跑本机自测（见下）确认工具本身没问题；再看失败原因——`TimeoutError` = 目标/代理不通，
`ClientOSError(错误码 1225)` 多半是代理地址连不上。免费代理大多已失效是常态。

**Q：怎么在本机自测？**
```powershell
python -m http.server 8080        # 然后目标填 http://127.0.0.1:8080/
```
注意它**只支持 GET**：填了「上传体」它会回 `501`（你的工具仍会把它算成"有响应"），
想测上传得自备一个回显服务。**测本机就别选代理文件**，否则是"经代理访问本机"。

**Q：中文输出乱码 / 报 UnicodeEncodeError？**
不用管，脚本检测到输出被重定向时会自动切到 UTF-8（`errors="replace"`），直连控制台走系统编码。

**Q：并发填多少合适？**
本机自测 5~20 即可；测远端建议从 10 起步，看 QPS 和失败率再加。并发不是越大越好，
目标带宽、文件描述符上限、代理质量都会先成瓶颈。

**Q：能不能只跑到某个流量？**
能，见 §5。示例：`--max-traffic 1t -b 64k` = 一直跑，直到上下行合计 1TB。
